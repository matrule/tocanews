## What the integration does

A practice management system holds the matter, but a good deal of the work on a matter happens somewhere else: in a third-party portal, a form on the firm's website, an outside service, or a desktop application the firm has run for years. People bridge those gaps by hand, reading from one screen and typing into another.

Toca closes them. It connects Actionstep to a firm's internal and external systems, including older software and files that were never built to be connected, and it does so by configuration in Toca rather than a custom API project for every link. Two things follow from that:

* **Integration.** Actionstep exchanges data with the other tools a firm relies on, so a detail is entered once and used everywhere it is needed.
* **Connected workflows, end to end.** An event on an Actionstep matter can start automated work in other systems, and work that begins elsewhere can open or update the matter.

## How it works

| Stage | What happens | What it takes away |
| --- | --- | --- |
| 1. Intake | Information arrives from third-party portals, web forms and older desktop files. | Typing it in again by hand. |
| 2. Toca and Actionstep | Toca creates the matter in Actionstep, passes the data to the systems that need it and triggers the next step for each team. | Writing and maintaining integration code. |
| 3. The result | Actionstep and the systems around it stay in step as the matter moves, with a record of each automated step. | Reconciling one system against another, and the waiting that slows a matter down. |

## Keep the system you run

Toca works alongside the practice management system a firm already has, so nothing is replaced. Actionstep stays where the matter lives and Toca reads from it and writes back to it. We do the same for firms on other practice management systems.
